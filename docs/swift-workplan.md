# Reviewrr for macOS — parallel work plan

**Status:** tracks A–E landed and integrated; this remains the ownership map for further parallel work
**Last updated:** 2026-09-06

Reviewrr is now a native SwiftUI macOS app. The other documents in `docs/` describe the product
(`product-vision.md`), the MVP behaviour contract (`mvp-plan.md`), AI provider expectations
(`ai-providers.md`), and the architecture of the earlier React/Wails implementation
(`architecture.md`, `architecture/**`). Product intent in those documents still holds; their stack
details do not. This page is the Swift implementation's plan of record.

## Where the app stands

All five tracks below have landed and are wired together: the dashboard is the home surface, the
workspace has file triage and a split/unified diff, discussions carry resolution state and CI checks,
credentials are diagnosable, and AI runs against five providers with a structured result schema.
See [roadmap.md](roadmap.md) for what each of those does and does not cover.

## Target shape

```
Dashboard (watched projects, cross-repo PR inbox)
        |  open a PR
        v
Review workspace
  left    file tree, categories, filters, review progress
  center  split/unified diff, drafts, inline threads
  right   AI (ask, analysis, findings) | Conversation | Checks
```

## Shared contracts

These are owned by the integrator. Feature work builds on them and does not edit them.

| Contract | File | What it gives you |
| --- | --- | --- |
| `GitHubAPI` | `Services/GitHubAPI.swift` | Request building, auth headers, status/error normalization, `Link` pagination, GraphQL, rate-limit and OAuth-scope headers, `GitHubHost` for GitHub.com and Enterprise Server |
| `GitHubError` | `Services/GitHubClient.swift` | Normalized, user-facing failure categories |

| `AppSettings` | `Models/Settings.swift` | Forward-compatible preference blob; new fields decode with defaults |
| `KeychainStore` | `Services/KeychainStore.swift` | Multi-account secret storage (`github-token`, `ai.<provider>`) |
| `Theme` | `Design/Theme.swift` | Colors, mono fonts, `reviewrrCard()` |

Rules for shared contracts: additive only, never rename or remove an existing field or exported
signature, and never edit a file you do not own.

## House rules

- macOS 14 deployment target, SwiftUI, Swift 5 language mode, **no third-party dependencies**. The
  project is generated by `xcodegen` from `project.yml`; new files under `Sources/Reviewrr` are
  picked up automatically.
- Comments explain *why*, not *what*. Match the density and tone already in the codebase.
- Views read `AppModel` through `@EnvironmentObject` for existing published state. Feature state
  belongs in that track's own `ObservableObject`, constructed with an `AppContext`.
- Types in `ViewModels/` and `Services/` must not reference view types: they compile into the unit
  test bundle, which excludes `Views/`.
- Prefix new shared-sounding type names with the feature (`InboxPR`, not `PR`) to avoid collisions
  between tracks working in parallel.
- Never log or persist a token outside the Keychain.
- AI is read-only: it never approves, rejects, posts, or edits. A human turns an answer into a draft.

## Verification

Full-module type check, safe to run while other tracks are editing:

```bash
xcrun swiftc -typecheck -sdk "$(xcrun --show-sdk-path --sdk macosx)" \
  -target arm64-apple-macos14.0 $(find Sources/Reviewrr -name '*.swift')
```

Errors in files another track owns are transient — report them, do not fix them. The integrator runs
`make build` and `make test`.
